# Аудит и улучшение интерфейса GrabYou

## Задача и направление

GrabYou — сервис срочных предложений локального бизнеса. Посетитель главной
должен понять сценарий «найти рядом → оплатить → забрать по QR» и открыть
приложение. Для бизнеса важны условия подключения и понятная заявка.

Основной подход — impeccable: уточнение существующей визуальной системы.
Сохранены лайм, чернила, вордмарк, карта Петербурга и реальные экраны приложения.
design-taste-frontend применён к композиции, emil-design-eng и
frontend-ui-engineering — к взаимодействиям и доступности. Для движения
использованы animate, choreograph и animation-performance; для крайних данных —
break-ui; для проверки — playwright-skill. Объём кода ограничен по принципам
karpathy-guidelines и ponytail.

## Проверки

По пожеланию владельца возвращены бесшовная бегущая строка справа налево и
анимация трёх точек под запросом про букет. Главный экран появляется одной
группой за 480 ms. Циклическое движение можно остановить кнопками; вне экрана
и в скрытой вкладке оно приостанавливается, при reduced motion заменяется
статичным представлением. Проверка направления, стыка цикла, паузы и reduced
motion находится в `scripts/verify-motion.cjs` и запускается тем же Playwright runner.

- Production-сборка Docusaurus: `npm run build`, без предупреждений компилятора CSS.
- Видимый Chromium через Playwright: три страницы на 390, 768, 1440 px;
  переход к приложению, ссылки каналов, мобильное меню, Escape, переход к партнёрам.
- Клавиатура: видимый фокус, FAQ, модальное окно, возврат фокуса,
  исключение фоновых элементов из Tab-навигации.
- Форма: пустые поля, пробелы, неверные телефон/email, один символ,
  длинное название с диакритикой и emoji, длинный адрес/email, лимит 300 символов.
- API-моки: ошибка → повторная попытка → отправка → успех; блокировка повторного
  нажатия, сохранение черновика, очистка после закрытия подтверждения, таймаут.
- Дополнительно: 320 px, текст 200%, тёмная тема и prefers-reduced-motion;
  отсутствие горизонтального переполнения и обрезанных основных действий/заголовков.
- Axe 4.14.1: 12 сочетаний страницы/темы/ширины, 0 нарушений выбранных правил
  WCAG 2 A/AA и 2.1 AA. [Результаты](axe-results.json). Отдельно проверены открытые
  меню и форма в тёмной теме, hover навигации.
- Сборка с `BASE_URL=/hosting_grabyou/`: все три страницы, изображения и локальные
  ресурсы загружаются без 4xx/5xx и ошибок JavaScript.
- CORS preflight текущего Pages-домена и основного домена, исключение постороннего
  origin: `node scripts/verify-partner-api.mjs`.
- Механический детектор impeccable и `git diff --check`: ошибок не обнаружено.

Повторяемая браузерная проверка находится в `scripts/verify-ui.cjs`.
Запуск через установленный навык Playwright:

```powershell
npm run build
npm run serve -- --host 127.0.0.1 --port 3001 --no-open
# В другом терминале:
node C:/Users/donsk/.codex/skills/playwright-skill/run.js scripts/verify-ui.cjs
```

`TARGET_URL` меняет адрес, `PW_ARTIFACT_DIR` — папку скриншотов.
`PW_PREVIEW=1` открывает переключатель Demo data / Worst case / Empty для реальных
полей формы. Этот переключатель существует только в проверочном браузере.

## Ограничения

Отправка настоящей заявки в Telegram не выполнялась: браузерные запросы формы
подменены моками, чтобы не отправлять тестовые персональные данные. Реальная
доставка зависит от окружения Vercel и переменных Telegram. Локальный Docusaurus
serve не запускает serverless-функцию.

Это проверка Chromium с эмуляцией размеров, не физический iPhone/Android и не
проверка VoiceOver/NVDA. Автоматическая проверка доступности не заменяет такую
проверку. Установка приложения, покупка и оплата во внешних каналах не выполнялись.

Отдельных lint/typecheck/test-команд в исходном package.json нет; использованы
сборка, браузерный сценарий и проверка API. Публикация зависит от имеющегося CI;
настройки хостинга этим изменением не переопределяются.
